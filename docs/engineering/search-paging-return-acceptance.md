## 修复与本机复验

原先结构化搜索视图每次重新出现都会 `clear()`，再用默认类别搜索。现在通过 `MusicCatalogBrowser.searchIfNeeded` 保留相同查询／来源语言的类别、已加载内容与游标；新查询或语言变化仍重新请求，中断的初始请求可以重新开始。真实查询／来源改变仍由共享搜索服务清理旧状态。没有改动 provider、缓存格式、播放、队列或数据模型。

新 Release `20261021.7305`（`com.muses.acceptance.search-return-fix-oct21`）实际复验：

- 同一真实 Roselia／YouTube／歌曲路径取得第二页；首页／后退后仍为“歌曲”，原首屏与第二页末端保留。
- 返回后再次点击目录“加载更多”，保留的游标成功取得下一页；实际末端显示一逢のFull Glory (instrumental) 等新增歌曲。
- 补充搜索实际请求 40 项并绘制新增末端；再次首页／后退，歌曲类别和已加载目录末端仍保留。
- 滚动位置回到顶部，补充结果的展开状态也会收起；本轮接受的是类别、内容和游标保留，没有宣称滚动／展开状态恢复。

40 是补充搜索请求上限，不能当作显示条数：修复轮的来源排名变化，20 项与新 40 项规范化响应的身份并集为 44。实现保留原项再追加新身份；本轮观察了原有开头与新增末端，没有把并集计算当成原生逐行核验全部 44 项。
