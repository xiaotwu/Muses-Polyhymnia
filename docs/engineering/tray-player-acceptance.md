# Tray keyboard handoff and controls — XW-103

XW-103 is a focused child of XW-72. The human established a repeatable native failure: when another application was active, clicking the lyre and immediately pressing physical Escape left the card open. Clicking inside the card before Escape allowed it to close. This adds a specific background-entry condition to the narrower accepted XW-63 paths; earlier tool-delivery limitations remain separate evidence.

## Change

`TrayController` completes its window keyboard handoff in `popoverDidShow`, after the native popover finishes appearing. It checks that the notification belongs to the currently shown popover before making that window key and ordering it forward. It does not activate the application or explicitly raise its main window. Existing local dismissal still consumes Escape only from the card's window; native menus and other windows retain their input. On the matching close notification it releases the hosting tree, including overflow-text animation; a late close from another popover cannot release the current one. There is no global keyboard monitor or new permission.

The song title is now a native button that closes the card and invokes the existing main-window action. Its accessible label remains the full actual title; the old upper-right open icon is removed. The empty-track title keeps the same open action.

Following the human's layout refinement, the bottom row is Playback mode / Previous / Play / Next / More. Equal flexible gaps and equal outer/adjacent control widths keep Play centered. More is the rightmost control. The card no longer exposes a volume knob or mute action. Audio-output choices remain in More, using the existing shared audio-device service. Transport still uses the single app-lifetime PlaybackService.

The latest request integrates Shuffle into the playback-mode button and removes its separate More entry. The tray keeps the existing Off → One → All repeat order, then adds Shuffle before returning to in-order playback. In-order mode uses a numbered-list glyph, replacing the intermediate right arrow. This tray-only adapter invokes the existing queue setters; other repeat buttons and the queue/persistence implementation are unchanged. It reads actual shared state, including externally combined settings; Repeat One is displayed when it governs completion. Switching to another mode explicitly normalizes repeat/shuffle. More explicitly opts into `.labelStyle(.titleAndIcon)` for Audio output, output devices, Share and Quit; native macOS menu labels otherwise omit these icons by default, as described in [Apple's menu documentation](https://developer.apple.com/documentation/swiftui/populating-swiftui-menus-with-adaptive-controls). The tray Quit label is shortened to “退出” / “Quit”. The status-item lyre is lowered by one 2× backing pixel (0.5pt), retaining its full ink in the 18pt canvas; the shared centered PlayerBar image is unchanged.

The final human decision replaces the intermediate 4:3 request with **16:9**. Title and artist each use one line, with a smaller 11pt artist. Content uses 294pt width, 154pt minimum height and 16pt horizontal/12pt vertical padding. The r4 candidate measured a steady **320 × 180pt** on this host, across 104 passive samples. Minimum height still permits error content to grow. Earlier native cards measured 358 × 215pt and a steady 294 × 220pt; opening/closing animation frames are excluded. Those are superseded checkpoints, not the final dimensions.

`DelayedMarqueeText` measures only its own text and viewport. Visible overflow pauses for two seconds, moves at 24pt/s to reveal the full tail, pauses and returns. Short text stays still. Text/width changes restart the cycle, Reduce Motion uses a static single line, and the accessible full label does not move or change with the offset. The per-frame keyframe closure only transforms that text leaf; no playback clock or collection animation was introduced. Closing the popover releases its host. Four new behavioral tests evaluate the actual SwiftUI keyframes and visibility/reduced-motion/invalid-geometry gates. The mode integration adds five queue-cycle, active-insertion/anchor, combined-state, idempotent-shuffle and persistence tests. The final r6 focused run passed **90 tests in seven suites** (0.393 seconds), including the existing queue and persistence suites; private Release compilation also passed.

The source-layout assertion requiring a tray volume knob was removed because the user explicitly replaced that contract. No new source-string or low-impact layout tests were added.
