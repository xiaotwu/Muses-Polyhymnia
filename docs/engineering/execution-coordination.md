源码与证据读取、各对话自己的计划可以并行。共享工作区的源码修改、构建、测试、Git 操作和原生运行互斥；性能采样期间也不运行其他构建或测试。所有原生实例仅由当前拥有运行阶段的对话操作。

协调目录位于 `~/.muses/tmp/engineering-oct08`，不提交到仓库。`plan.json` 由当前协调对话维护；每个执行对话仅更新自己的 `status/<key>.json` 和 `runtime-complete/<key>.json`。后者表示该对话的当前运行阶段已完成、清理并释放资源，不代表 Linear 所有外部/延期验收均通过。

使用原子创建目录获取 `workspace.lock`；原生阶段按 `runtimeOrder` 获取 `runtime.lock` 后再获取工作区锁。锁中记录拥有对话、任务和取得时间；完成后只释放自己的锁。不得凭等待时间抢占锁，必须核实所属阶段、进程与资源已经结束后才能修复失效锁。等待阶段继续独立只读分析，不重复构建或争用用户输入。

每个对话读取当前 AGENTS、技术分类文档及对应 Linear，复用已完成证据；只有当前缺口触发修复。不在开始时重新做全量测试。代码修改采用小范围提交，在持有工作区锁时验证、提交、推送；其他执行者先核对最新源码再进行其运行阶段，不重置或覆盖他人改动。

原生验收使用独立 `com.muses.acceptance.*`、数据/cache 与私有证据目录。只操作已授权 `test` 歌单，保留生产数据、普通应用和 Keychain；不操作 Liked、远端写入、权限扩张、OS 辅助功能/显示/输出设备变化或安装发布。真实账号/设备/权限不足的分支如实保留，不制造证据。临时偏好恢复、精确拥有的进程/窗口退出、原始数据核对和过时构建/cache 清理完成后才释放运行阶段。

各对话将具体原生状态、测试/测量条件、修复与残留边界写入自己的结果文档，并更新自身 Linear 子项。协调对话汇总结果和交叉影响；父任务在完整剩余条件满足前保持开放。外部条件受限时结束并清理当前可执行阶段，记录限制，允许下一个对话继续其独立范围。
