# 普通 Playlist 元数据与删除验收

2026-10-11，沿用修复源码 `3b44632` 的 Release 产物和匹配 App Intents 元数据，在新的可写隔离副本中完成一个普通 Playlist 小节。未修改应用源码。此单元补充 XW-85 的普通歌单分支；XW-9/16/26 的其他状态仍由各自任务管理。

## 本轮操作与结果

通过生产界面从两首既有 YouTube-backed libraryMember 曲目新建自有歌单、追加第二项并打开完整表。这两首歌不属于受保护的原 test 导入。每次追加后读取实际 Playlist、Item UUID 和 Track/video 身份，确认顺序为 0/1。

在同一保留详情中打开 Edit Info。Cua 读取实际焦点和值；Control-E 后输入唯一数字后缀，完整文本与“原标题＋后缀”相符，暂停、当前曲目和播放记录不变，再点击 Save。同一详情立即显示新标题。第二次原生 Save 恢复原标题，同一详情也恢复。删除前核对实际歌单 UUID 和仅包含两项的预览，再删除自有歌单；其 UUID 和两个 Item UUID 均从实际数据库消失。

这是 Cua 原生操作验收，没有新增 XCTest 通过结果。执行方直接检查了可见界面；Cua 原始界面与图像保留在执行对话的工具记录中，本轮没有独立导出的本地图像文件。协调方独立核对七个只读 SQLite 检查点：initial、created-one、prepared-two、title-saved、title-restored、delete-ready、deleted。每个检查点完整性正常，655 首 Track 保留，仅 title-saved 存在预期标题差异，其他 654 首曲目保持原值；原有歌单、导入及其 506 项顺序、笔记、书签和修订均保留。18 张未涉及修改的表逐值比较一致。

所有检查点的 60 条播放事件、播放计数、lastPlayed 和当前队列/会话值保持；仅既有恢复路径补齐九个 historyRecordID，以及 ORM 和会话/保存时戳记账变化。没有在本轮测到新增播放副作用。停止后的实际数据库另行保留后再清理，未用重置副本冒充原生恢复或删除。

## 已保留的先前失败

第一次 XCTest 因私有分页断言不适用于单页歌单而失败。第二次脚本把 Command-Right 用作文本定位；应用将其绑定为下一首，数字进入标题中间，断言在 Save 前失败。停止库实际记录了一次 skipped 事件，以及当前歌曲 playCount 12→13 和相关队列/会话变化。该副作用发生在隔离副本，记录完整保留，未改写成“无播放影响”。

第三次在新增的只读焦点检查处返回 AX -25211（kAXErrorAPIDisabled），尚未发送 Control-E 或输入数字，没有 Save，也没有新增播放事件。这只说明 runner 的直接 AX 读取不可用；先前 XCTest 操作仍然有效。本次改用现有 Cua 能力完成输入和验证，没有申请新权限。

三个失败的完整结果和实际停止数据库均保留。它们不证明产品元数据刷新失败，也不被本次通过结果覆盖。
