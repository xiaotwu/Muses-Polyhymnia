# 导入署名与封面呈现

2026-10-14 用户追加范围，对应 XW-97 与 XW-98。XW-96 已按实际人类操作验收收尾，严格小于 300ms 的计时仍未验证，不阻断本节。以下是当前修复合同与实现记录；原生结果须另行记录，不以源码推断为通过。

## 导入署名：XW-97

用户报告已发布版的艺术家仍是前歌单持有人。关闭的只读实际库副本确认：655 个 Track 使用该错误旧值，其中 514 个仍有精确 videoID 对应且一致的导入条目来源署名，141 个没有保留来源条目。当前导入的 owner 已变化，旧名称没有保留在 owner 字段中。现有 XW-94 仅登记保留导入的 owner，因而把这种失去来源事实的旧值当作独立 metadata 保留。表格已经使用共享显示投影；清缓存或替换一个 Text 字段不能解决。

修复采用资料库核对中的显式预览：输入已确认错误的旧署名，按 Track UUID/videoID 限定候选；区分已验证艺人、保留条目的来源署名和无法解析。不能硬编码用户名，不能从任意 Track/Item 差异推断用户没有编辑。无可靠来源的行保持明确状态，是否清掉已确认错误的旧值由预览选择，绝不填入猜测艺人。

新版本中的入口为“设置 → 资料库核对 → 修复旧导入署名…”。输入完整错误署名后先预览；默认跳过未解析项，只有显式勾选才清空这些行。应用后可在同一面板撤销上次修复。此流程尚未在用户的正式资料库执行。

Apply/Undo 使用 fresh-context、当前值核对和单次事务；预览过期、来源变化或后续手工编辑时停止，失败回滚。只修改已确认的 artist 字段，保留 UUID、收藏、历史、队列、导入条目、顺序及 revision。独立恢复记录保存确认事实；冷启动只核对与加载显示校正，不自动写 Track。来源署名不冒充真实音乐艺人。无 schema 或手工来源标记扩展。

## 焦点卡、聚焦横栏与封面：XW-98

- 歌曲/歌单焦点卡整体 3:4：方形封面加 `width / 3` 的文字区。卡宽适度增加，两侧使用更多相邻卡；最多仍挂载 13 张邻卡。封面墙保持原几何。
- 文字区保留标题和艺人，随用户字号与可用高度减少额外标题行或专辑；不缩小用户选择的字体。焦点、键盘、指针、滑条、菜单、ember 激活和集合播放顺序继续沿用。
- Muses 聚焦使用最多六个稳定、去重、来源合格的推荐，放在同一 lazy 横向滚动栏。账号模式没有本地 recent 回退，保留各卡的来源与既有 Open/Play 上下文。
- YouTube 封面沿用实际渲染像素需求，包含现有 Retina 与 fill 裁切预算。本轮补齐低档默认图/MQ 的不足档位；需求超过 480 源像素时保留现有 maxres 优先、SD/HQ 回退，避免已有 HQ 库的中等封面降档。持久图片 URL、视频身份及解码/取消/缓存边界保持；实际副本 673 条均是 HQ 地址，未发现原有统一大图路径的确定性降采样错误，因此不宣称这 673 条均提升清晰度，也不宣称无测量的性能改善。
