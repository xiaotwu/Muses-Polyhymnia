# Pull 原生错误、草稿保留与重试

2026-10-11，在 macOS 27.0.1（26A434）完成 XW-84 的原生验收小节。应用仍使用 `3b44632` 的 Release 可执行文件与匹配元数据，未修改应用源码或注入保存异常。真实 Pull Preview 显示磁盘空间错误，保留用户调整的顺序草稿；释放空间后，同一面板、同一进程点击 Apply 成功，随后正常退出并冷重开仍保留结果。

## 真实来源与前置写入

用户在独立 Keychain 的隔离版亲自完成只读连接，并指定新的 `test` 歌单。原生账号页面确认读取账号数据已允许、管理歌单未允许。指定链接的匿名 yt-dlp 导入返回“歌单不存在”；随后原生 Account playlists 刷新通过已认证 Data API 成功导入同一精确 playlist ID，完整快照为 530 项、11 页。因此匿名导入失败没有阻断已认证 Pull。

自动连接和显式账号刷新在隔离副本增加三个导入歌单、1,060 个条目和 16 首 Track。原有 655 首 Track 的业务字段、五个导入歌单及条目、60 条播放记录保持。前置导入、生成预览和 Apply 分开建立只读 SQLite 检查点，避免把准备阶段的写入混入失败回滚比较。旧 seed 的 506 项 `test` 与本轮 530 项来源不是同一个歌单。

## 两种真实故障尝试

第一次只对自有 SQLite 库保留一个独立 `BEGIN IMMEDIATE` 写事务，不写业务行，30 秒自动回滚释放。原生 Apply 等待，GUI 读取超时；锁释放后保存成功并关闭预览。这是无效的错误触发方式，不计为错误展示或重试通过。该次实际排序将原第二项移到末位，530 个 occurrence 全部保留；没有按预期交换前两项的结论。

随后正常退出候选，将完整自有 data 目录复制到固定 128 MiB 的 HFS+J 可写映像，挂载在原隔离 data 路径；原目录保留至验证结束，映像、证据及缓存位于该卷之外。先验证只填充专用卷至可用/空闲空间均为零，再截短并移除自有 filler，实际写入能够恢复。独立恢复进程提供 30 秒上限，主文件系统仍有充足空间。

同一隔离版从该卷启动，通过正式 Pull 菜单重新获取完整远端快照。预览如实显示 0 项远端变化、529 项本地变化、0 个冲突。自动化拖拽没有可靠改变新草稿，用户亲自将 `Resonating Beats` 移至第一行；协调方核对截图和 AX 后建立失败前基线。

## 错误、回滚与同面板重试

- 仅填满专用卷后，真实 Apply 返回红色错误：`The operation couldn’t be completed. (NSSQLiteErrorDomain error 13.)`。预览没有关闭，首两项仍为 `Resonating Beats`、`ティファニーに連れてって`，Apply 未被 AX 标为禁用。
- 在空间仍为零时保存失败后的只读检查点。失败前后全部 27 张表的列类型与读取值一致，包括 SQLite/Core Data 辅助表；没有部分提交。
- 恢复进程按释放信号在约 21.32 秒时移除压力，释放约 124 MB，独立小文件写入通过。没有关闭面板、重新检查远端、重建草稿或重启应用。
- 在同一 PID 中再次点击 Apply，面板正常关闭，详情首项即时变为 `Resonating Beats`。全部 530 个 occurrence 身份保留；相对失败前基线，恰好交换首两项，其余 528 项顺序相同。RemoteShadow 指针与原修订保留，Base 更新为已接受的完整远端快照，lastSyncedAt 前进，仅新增一个 beforePull 和一个 Base。
- 正常退出后，通过原生应用入口重新启动到新 PID；歌曲表格第 1/22 页仍以相同两项开头。Import、Item、Revision 和全部 60 条播放记录与成功提交后的检查点完全一致。这个冷重开由显式启动触发，不属于 XW-75 的 Intent 自动冷启动。

本轮没有自然冲突，因此接受的是修改后的**顺序草稿**保留，没有新增 Keep Local / Use YouTube 冲突按钮的原生通过结论。既有受控冲突和原子保存回归、[真实磁盘写入错误 778 回归](pull-disk-recovery.md)继续有效；这次原生错误 13 是独立的空间耗尽路径。没有远端 Push/manage、远端歌单修改或权限扩展。

## 数据与收尾

最终隔离副本为 671 首 Track、8 个导入歌单、2,221 个导入条目和 60 条播放记录。原始 Track 业务字段、原五个导入集合、其它既有用户数据保持；Track 的 ORM 版本计数和生命周期时戳单列。队列 JSON 的逻辑内容保持，仅既有恢复逻辑为九项历史补齐 historyRecordID，不声称全部数据库字节不变。

完成原生 Sign Out，仅清理隔离候选的登录；恢复其原始空偏好域后正常退出。确认自有进程退出、数据库无打开文件，正常卸载专用卷，移除候选、data/cache、原自有目录副本和映像。十二项保护哈希一致，源 seed 仍为 0400；正常应用、当前构建和正常凭据保留。
